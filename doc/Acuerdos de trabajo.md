## Acuerdos de trabajo en equipo

### Estrategia de trabajo
El equipo no maneja roles fijos para el desarrollo del proyecto (modelo conceptual, lógico, SQL, etc.) pero existe un lider tecnico: Santiago, que nos ayuda a coordinar tareas. Inicialmente se planteó dividir el modelo conceptual por partes entre los integrantes, pero se optó que el modelado debe realizarse de forma conjunta, por lo que se descartó esa estrategia. El equipo trabaja a medida que se van entregando los temas en clase: cada tema nuevo se aborda en conjunto una vez el equipo tiene el conocimiento necesario.

Sí existe repartición de responsabilidades para tareas secundarias/administrativas, asignadas reunión a reunión:

### Comunicación
- Reuniones virtuales: Microsoft Teams
- Reuniones presenciales: instalaciones de ICESI, generalmente fuera del horario de clase
- La frecuencia se define según necesidad y avance del proyecto

### Control de versiones (Git)
- Se trabaja con una rama por funcionalidad (feature branch); cada integrante crea su rama y luego se integra a develop para finalmente pasar la version final a la rama main mas adelante.

Manejo de imprevistos
Si ocurre un evento externo que afecte el cumplimiento de compromisos o que la mayoria del equipo cancele para la fecha previamente asignada, el equipo ajusta fechas y tareas en la siguiente reunión, dejando constancia en el acta correspondiente.
